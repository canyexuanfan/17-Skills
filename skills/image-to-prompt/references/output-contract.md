# 完整提示词输出约定

## 单一交付

默认返回一个 `text` 代码块，块内是一份自然语言生成指令，可分段并用少量小标题组织。小标题不是图内文案，图内文案另用引号明确标注。不要输出 JSON、XML、内部事实表、节点 ID 或需要拼接的正负提示词。

代码块必须独立：没有参考图也能知道画幅、区域、主体外观与位置、连接/遮挡、文字原文与承载面、背景、光影、色彩、质感和禁止变化的细节。除用户明确要求多版本外，只给一个完整版本。

图像质量不足导致关键不确定时，在块外简短说明；不要把“不确定”“待识别”等说明画进作品。不能恢复的文字不编造。若用户严格要求只要代码块，写清可确认内容，不假称缺失信息已经恢复。

## 信息顺序

### 开头：高影响结构摘要

先写实际画幅与媒介，再用自然语言说明全局布局和决定辨识度的关系。不要只用主题和氛围开头，让具体结构拖到末尾。

整体概括必须与细节段相容：不能开头说全部对象限制在各自区域，后面又要求同一对象越界；不能开头说全图一个连续实景，后面却描述不相容的独立底图。

### 全局布局：可定位的区域

逐一说明主要区域的形状、范围、比例、填充、边界与连接；描述主体中心与体量、关键负空间、机位和透视。区域是否独立、重叠或嵌套必须明确，不能把“分区”当成“互不相交的独立图片”。

### 关键关系：让对象真正连起来

把跨区对象、共享对象、局部遮挡、动作端点、接触或间隙、视线写成完整关系句。对重要边界同时交代底图边界与前景可见性。没有这些关系的图跳过，不照模板新增。

### 逐区细节：外观与文字一起归位

每个区描述主体、背景、环境、被裁切部分、装饰及文字组件。文字要同时写出父容器的位置、形状、底色以及子项的原文、对齐和层级，不能把内容移到另一个区的段落里。

同一跨区对象在后文继续用明确称谓，不被重新引入成“另一只/另一个”。重复款式的不同物体则需分别计数并定位。

文字主导时，字形骨架、笔画与字腔、逐行可见字面框、行间空隙、字色和外部留白与原文一样重要，不能当成次要质感拖到最后。连续背景主导时，先写亮暗包络、形态、路径、宽窄与边缘进出位置，再写沿程配色；不能只给风格标签。

### 风格：分配到实际区域

用具体的色彩、轮廓、线条、笔触、光影、材质与成像说明风格。不同区域的光、透视或媒介可以不同，描述各自差异与整幅的共同色调，不为了统一风格而重做空间。

### 末尾：少量高风险约束

用几句自然语言重申最容易被改动的结构与关系，再列本图相关排除项。只强调可见且重要的约束，不重复全文，不把“严格、完美、一模一样”当作缺失的描述。数字、尺度、定性描述只从同一已核对基准压缩重述，末尾不能首次引入另一种字重、位置或物理光效。

## 位置表达的判定

| 过于宽松的表达 | 需要补充的信息 |
| --- | --- |
| 主体在某个大区 | 在该区哪侧、相对全画布的中心与可见体量 |
| 有若干分区 | 可辨数量、具体边界、尺度、连接方式 |
| 有图文信息 | 背景承载面、整体位置、层级、内部对齐 |
| 对象跨出画框 | 哪条边、哪一段、越界点、连续路径、前后与终点 |
| 对象相互互动 | 动作节点、共享物体、接触位置、间隙和视线 |
| 风格柔和 | 真实光源大小/方向、阴影边缘、对比、饱和度与成像；抽象色场不能据此虚构光源 |
| 大号粗字 | 逐行字面框、笔画/字腔比例、骨架特征、行间空隙与留白 |
| 居中排版 | 哪些组件共轴、各自范围、上下沿和内部间隙，不默认等宽 |
| 多色柔焦渐变 | 主要亮暗形状、边缘、走向、宽窄、面积、过渡带及是否真有聚点 |
| 一个近似某物的标识 | 实际路径、开闭、交叉与负空间，不能只给物体名称 |

这些是改写方向，不是可照抄到目标图片的内容。只有实际存在的项目才补充。

## 严禁外部依赖

禁止“如参考图”“与原图一致”“按附件”“之前那个”“文字照图”“其余不变”“同上”等指令性省略。逐一改成实际视觉内容。

若这些词本来就是图中正文，可作为明确引用的图内原文保留，不因词匹配误删。模板占位符同理：禁止未填模板，不禁止忠实转录真实字符。

不要把本地路径、测试文件名、旧模型名称、对比评语、工具过程或推测的制作参数加入生图指令。对特定平台参数的适配需用户明确要求且能力可核实，默认保持模型无关的自然语言。

## 篇幅与细节预算

不设必须凑够的字数。简单作品完整描述后可以很短；复杂作品需要足够篇幅，不能为了简短省略区域、文字、对象和关系。观察到的新事实才值得增加句子，近义词堆积不算更多细节。

长提示词中优先保留画幅、区域、关键对象几何、局部遮挡、明确文案及文字位置；文字主导时保留字形/字面/空隙，抽象图保留连续色场包络/路径/边缘，这些不是可删的微小细节；再保留真实风格、环境、微细纹理。不得以缩短为由删除重要内容；不得以详细为由增加没有证据的道具、服饰、光效或故事。

## 修订交付

用户反馈偏差时先核对原图，再输出完整的新提示词。只改必要的目标约束，移除旧的冲突句；不能只附一个补丁让用户自行拼接，也不能让新旧要求同时存在。

用户要求比较分析时，可在提示词外给证据层面的差异说明。用户要求维护 Skill 时交付规则文件，不擅自运行生图或给某个测试样本生成答案。

# xweb — 用命令行读 X（x.com）

**Agent 操作手册。** 前半部分是"用户说什么 → 你跑什么"，后半部分是**错误解释**与**边界**（这两块最容易答错）。

安装：见仓库 README（`install.sh` / `pipx install .` / `python3 -m xweb`）。没装就先跑 `xweb caps` 看能不能用。

---

## 0. 三条命令确认环境

```bash
xweb doctor            # 环境自检
xweb caps              # 当前模式（访客/登录）能做什么，一屏看清
xweb elonmusk          # 冒烟：默认子命令 = user
```

⚠️ **全局选项 `--json` / `--verbose` / `--dry-run` 必须写在子命令之前**：`xweb --json user X` ✅ / `xweb user X --json` ❌。

## 1. 用户说什么 → 跑什么

| 用户说 | 命令 |
|:--|:--|
| 「看看某人的资料/粉丝数」 | `xweb user <handle>` |
| 「查某人的推 / 他最近发了什么」 | `xweb latest <handle> -n 5`（**最新，最稳**）；要历史翻页 `xweb tweets <handle> --pages 6` |
| 「这条推文写了什么」 | `xweb tweet <id 或 url>` |
| 「这条推文下面大家怎么说」 | `xweb detail <id> -n 10`（含回复串） |
| 「批量看这几条推」 | `xweb detail id1,id2,id3 -j 6` 或 `xweb --json detail --ids-file ids.txt` |
| 「推特热搜 / 趋势」 | `xweb trends -n 20`（地区表 `--list`） |
| 「查股价 / 行情」 | `xweb quote NVDA --timeframe 1D` |
| 「搜推文」 | `xweb search "关键词" --product Latest`（**需登录**） |
| 「某人的粉丝/关注列表」 | `xweb relations <handle> --followers`（**需登录**） |
| 「看看这个社区」 | `xweb community <id\|url> --what posts` |
| 「我的收藏/通知/首页」 | `xweb bookmarks` / `notifications` / `home --latest`（**需登录**） |
| 「把结果给程序用」 | 任何命令前置 `--json` |
| 「发个推 / 点赞 / 关注」 | **先** `xweb --dry-run post "文案" --yes` 给用户看，**再**去掉 `--dry-run` |
| 「有没有现成命令能查 XXX」 | `xweb ops --filter '关键词'` |
| 「这个接口怎么调 / 参数是什么」 | `xweb op <名> --auto-vars`（自动补全必填变量） |

**逃生口**：`xweb ops --json` 列出全部操作；`xweb op <名> --var k=v` 直接调。多数常用操作预置了变量样例，免参可跑。

## 2. 访客态 vs 登录态

| | 访客态（默认，零凭据） | 登录态（用户自己填 cookie） |
|:--|:--|:--|
| 能做 | 资料、时间线、单推、最新推文、趋势、行情卡、推文详情+回复、社区帖子 | 上面全部 + 搜索、各 tab 时间线、粉丝/关注、收藏、通知、设置、发推与互动 |
| 不能做 | 搜索/粉丝/收藏/通知等（服务端只给登录用户） | — |
| 风险 | 零账号 | cookie = 账号完全访问权，**务必用小号** |

登录态由**用户自己**在浏览器拿 cookie 后交给 CLI（细节见 README「登录态」）。**不要把用户的 cookie 写进任何文件、日志或提交到仓库。**

## 3. 错误怎么解释（Agent 最容易答错的地方）

| 现象 | 真实含义 | 你该怎么做 |
|:--|:--|:--|
| `404` 且空 body | 该操作在当前模式下不可用（多数是**需要登录态**） | 先 `xweb login`，再重跑；仍失败就说明该操作对你不可用 |
| `Internal server error` | 服务端返回的错误兜底文案，通常是参数不合适 | 核对参数后重跑；不要据此判定"接口不存在" |
| 200 但没有数据 | 这次查询没有内容（该账号没这类数据） | 换目标或稍后重试，不要一次空结果就判定"能力没有" |
| 200 且返回了你传进去的值 | 参数形状不对（服务端把入参回显了） | 把入参从响应里抹掉再比对 |
| 时间线看起来很旧 | 访客的时间线有两种：一种能翻页且新鲜，一种是**跨年采样快照**（翻不动） | 要最新就换 `xweb latest <handle>`；CLI 会提示是不是快照 |
| 结果被截断（只有一部分） | 访客通道的结构性上限 | 要全量只能上登录态 |

**汇报原则**：说清"测过什么"和"没测什么"，别把"能用"说成"全能"；引用数据时说明是哪条命令跑出来的。

## 4. 写操作安全规则（硬要求）

1. **先 dry-run 再执行**：`xweb --dry-run post "文案" --yes` 会把要发的请求（凭据脱敏）打出来，确认后再去掉 `--dry-run`。
2. **不要批量跑写操作**（点赞/关注/删除成批跑容易被判定为滥用，也可能改坏用户的账号数据）。
3. **不可逆操作**（删推、删列表、清空会话）先跟用户确认，别自作主张。
4. **不要替用户发帖**，除非用户明确要求，并把 dry-run 结果给他确认。

---

## 5. 边界（对用户讲清，别把能用说成全能）

1. 访客态 ≠ 完整 X：搜索/详情/粉丝/收藏/通知这些服务端只对登录用户开放。
2. 时间线有两种（可分页且新鲜 / 封顶采样快照），CLI 会明确提示是哪一种。
3. 访客**拿不到全量历史**：页面 SSR 只有最新 5~10 条且无分页游标；GraphQL 时间线访客最多约 100 条采样。
4. `404` 空 body ≠ 一定"权限不够"（先排签名头）。
5. `Internal server error` 不能作为"接口不可用"的结论。
6. 空结果 ≠ 失败。
7. `HTTP 200` ≠ 值对（有些接口用 200 返回错误）。
8. 某个操作突然失效是正常的（服务端会调整接口）：以 `xweb caps` 的实时状态为准，或等新版本。
9. 风控：「机房 IP + 新 cookie」是高风险组合，优先让用户在本机跑、降频。
10. 合规：遵守 X 的服务条款；大规模取数请走官方 API。

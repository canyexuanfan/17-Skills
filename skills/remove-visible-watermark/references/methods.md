## 区域引导的文字掩膜

在 Agent 已确定的局部 ROI 中，用亮度中值残差、去饱和残差建立浅色字芯候选；通过连通分量的字高与基线共识筛出一行文字，再在有限邻域纳入暗描边、抗锯齿。1.3.0 允许读取框外最多 32 像素上下文进行中值统计，避免把用户的框边界当作真实图像边界；分类和最终写入仍限定在原 ROI 内，不把读上下文视作擦除授权。

ROI 高度只提供初始滤波尺度。具备足够内部支撑的亮种子先用小开运算分离一像素细桥，减少场景高光与字形粘连对行高估计的影响；细文字缺少内部支撑时保留原种子。根据可靠字行的顶端、底端中位数，可进行一次字高驱动的尺度重估。选定字形后，只在附近最多 3 像素范围恢复原亮种子，避免把原先整条场景边缘重新接回。这里不使用具体品牌、文字内容或样图坐标。

亮字芯很弱的细钩可能超出普通描边邻域，而暗描边仍然可见。对此先从已观察到的描边学习双侧暗谷对比度，以其下四分位和噪声门槛确定可靠延伸条件；只沿相邻强暗轮廓、在有界邻域内传播最多 3 步，再对新确认的轮廓补一圈较弱的抗锯齿证据。不把单侧物体边缘或较弱的孤立暗纹仅凭距离纳入，也不通过整体膨胀掩膜遮掉问题。

最后按字高限制闭运算与小孔填充，以覆盖与背景接近的字符内部弱区。允许少量字内背景参与修补，主要字间背景仍保留。上下文和几何约束减少了部分 ROI 敏感性，并不保证任意宽框、跨物体轮廓或低对比场景都得到相同且正确的掩膜。

1.2.0 不再用固定 `baseline + 3` 截断文字下界，而是按字高留出自适应余量，覆盖下伸笔画与倾斜字角。形态学扩张、闭运算与补洞受深色边缘约束，不越过明显更暗且缺少字形证据的像素，避免把邻近桌沿连入文字掩膜；这些约束仍不能从语义上判断物体。

分割后的文字掩膜额外生成 2 像素源排除圈，以防残余字边进入纹理供体或可信匹配。排除圈不扩大写入掩膜，也不作为要求用户手动膨胀修补区的理由。

此方法不认识“豆包”等词语，不加载任何字形模板。它也无法从语义上区分水印与正常文案，因此要先确定正确区域。浅色字芯与暗描边是适用条件，深色字或彩色图案应给精确 mask。形态学操作的定义见 [OpenCV 官方说明](https://docs.opencv.org/4.x/d9/d61/tutorial_py_morphological_ops.html)。

## 检测与配准

使用模板的高通形状、梯度和灰度一致性寻找有限候选，再结合反算后的字形残留改善与数值越界筛选。默认按右下角锚点，在局部窗口内搜索原生及画布等比例尺度。缩放在原画布坐标系中采样，避免直接缩放局部模板导致坐标相位错位。

检测分数仅用于当前模板的启发式排序和门槛，不是跨图片可比较的校准概率。当前未实现旋转、透视、任意平铺水印和语义文字检测。未知字体、裁剪缺字或不同重采样滤镜可能不匹配。不得用一两个样图的命中率声称通用准确率。

## 半透明模板反算

对背景不透明、逐通道采用普通 source-over 合成的情况，观测图像满足：

`I = (1 - alpha) * B + alpha * W`

若模板提供正确的 alpha 和前景色 W，且 `alpha < 1`，背景可由 `B = (I - alpha * W) / (1 - alpha)` 估计。本实现以浮点计算，再取整为 8 位；仅把修补掩膜内的结果写回。[W3C 合成模型](https://www.w3.org/TR/compositing-1/)

当前只接受 `encoded_rgb` 合成域，即与解码后 RGB 数值相同的域，不擅自改为线性光计算。真实叠加若采用不同色彩域、透明度、抗锯齿或重采样，反算可能出现字形残影、过暗边缘或越界数值。程序检查越界比例和反算残留等启发式指标，但这些检查不能证明原背景正确。

由公式可知，当 alpha 接近 1 时，误差被 `1/(1-alpha)` 放大；alpha 等于 1 时该像素的背景信息不可由这一个观测值唯一恢复。反算模块拒绝 alpha 不小于 0.95 的选中像素，而不是把除数强行压到一个小常数继续处理。

内置 WorkBuddy 模板来自用户提供的黑底样图。黑底观测只能得到预乘颜色 `T = alpha * W`，不能单凭一张黑底图独立确定 alpha 和 W。当前假定 W 为白色，即 `alpha = T/255`；这一假设不是官方模板真值。适用前提是同款字形、前景色、透明度和合成方式；两个真实样图都没有无水印真值。

## 纯色背景恢复

先检查模板字间空隙或邻近干净像素，要求颜色分布、空间覆盖与分区统计支持同一背景色，再以稳健估计的颜色填入掩膜。这样适合黑边、白边和确实平坦的背景。

检查通过仍只是“该颜色延续到被覆盖区域”的假设。纯色背景中原有的微小噪声或被完全遮住的细线无法由周围颜色证明。保护区和已知水印支持区会影响候选采样，避免把待去除字形当成背景。

## 受约束的 Exemplar 图像块修复

从缺口边界按已知像素可信度推进；在同图局部邻域中，寻找完整、未污染的原始图像块。匹配只比较目标块中的可信像素，使用高斯权重的 RGB 平方误差、小范围 RGB 均值偏移补偿，以及偏移和距离惩罚。RGB 补偿每通道最多 20/255，用于缓和局部照明差异；各补丁独立补偿仍可能留下亮度阶跃，不能单凭补偿范围宣称消除了接缝。此实现是自行编写的有界 exemplar 工程实现，使用 OpenCV 模板匹配计算，不是完整复刻论文，也没有实现随机 PatchMatch。

初始污染区域（包括仍被保护的水印）不能参与匹配或成为供体。显式 `--source-exclude-mask` 还可把用户指定的其他材质、文字或边界区域纳入排除范围；这些像素既不作为源图像块，也不作为匹配的可信上下文。新填像素可以较低权重辅助后续匹配，但供体始终来自原图未污染且未被排除的区域。1.2.0 的填充推进依据目标补丁内可用的可信支撑，允许从更远处跨过源排除圈匹配，不要求紧邻缺口的像素可采样；被排除的原图像素仍不可参与可信匹配。边缘使用反射上下文并同步反射排除掩膜，不把镜像水印当作干净来源。固定搜索半径、图像块大小和迭代上限，失败不返回半修好的图。

这类方法的依据是 [Criminisi、Pérez、Toyama 的 exemplar 图像修复](https://www.microsoft.com/en-us/research/publication/region-filling-and-object-removal-by-exemplar-based-inpainting/)。重叠补丁重建、多尺度与纹理距离可参考 [Newson 等非局部修复](https://www.ipol.im/pub/art/2017/189/)。[PatchMatch 原始论文](https://www.connellybarnes.com/work/publications/2009_patchmatch.pdf)中的搜索加速与图像重建是不同步骤：替换最近邻搜索本身不保证改善修复质量。本包未复制或捆绑这些开源参考实现。

相似纹理不等于原本内容。邻近材质不足、跨物体轮廓、复杂结构或供体内部偶然细节仍会造成拼接、重复纹理或小错位。报告的匹配误差仅为工程诊断；效果检查应结合选择区完整性、残字、纹理和边缘。报告继续保留真实原图准确率未知。

## 结构引导、重叠供体与梯度重建

`--refine consensus` 在初始 exemplar 后执行，必须配合显式 `--method exemplar`。Skill 对未知水印和有纹理背景默认传入这一完整流程；CLI 省略 `--refine` 时仍为 `none`，以兼容旧调用。它可用于文字分割掩膜、精确掩膜，以及同时有供体排除、保护区域的任务。`--quality` 仅控制初始 exemplar，精修使用 19×19 完整供体和独立预算。

**原图边界引导与初修信任检查。** 初修可能已经借入不合适的物体或颜色；直接以它作为完整匹配目标，会强化这些错误。当前实现先在允许掩膜内求解零引导梯度的调和背景，固定外部原图颜色。初修为该线性求解提供初值，但不决定其固定边界。随后检查初修与这一低频背景是否相容：局部至少需要 12 个未被排除的原图样本，RGB 最大通道偏差不超过 `max(12, 2.5 × 局部原图标准差)`，不一致区域再扩展 2 像素。通过检查的初修可作为弱匹配延续，其余位置使用边界引导。两者均为估计图，不是干净供体或真实背景证明。

**双侧可见线保护。** 单纯依照低频颜色也可能把真实细亮线误当成初修错误。代码仅在完整 3×3 梯度邻域都未受污染或排除的位置收集可见边缘，提出有界 Hough 线段；对横跨缺口的提案，遮挡两端各 32 像素范围内都至少需要 8 个方向一致的干净边缘样本。满足条件的狭窄线段支持区可保留初修作为弱匹配延续，即使它偏离低频背景。它不变成供体、不改变写入范围，也不证明隐藏线段一定如此。最多检查 128 个提案，可信边缘超过 5 万像素时这项保护主动跳过并报告警告。

**完整原图供体与有界搜索。** 每个 19×19 供体必须完整位于真实图像内，避开水印、显式源排除及其保护圈；反射出来的图像边界不构成新供体。先在 112 像素邻域查找；该邻域没有合格供体时，才搜索同一次已限定的上下文。有效匹配支撑不足的目标块可以继承受支持邻块的供体位移与颜色偏移，但继承结果同样必须满足完整源块约束。缺少真实来源时直接报错，不降低排除限制、不凭空加入来源。

**加权重叠融合与梯度重建。** 依据结构引导的目标、有效匹配支撑及有界颜色偏移选取完整供体。每个供体按目标块内的高斯空间权重和匹配误差贡献颜色及内部水平、垂直梯度，低支持传播块再降低权重；重叠处分别归一化为加权均值。融合后的背景颜色记为 v、独立供体梯度记为 g，仅在写入掩膜 M 内求解：

`min_u λ Σ_M (u − v)² + Σ_edges (∇u − g)²`，并固定 `u[~M] = 原图[~M]`。

颜色数据项限制低频漂移，梯度项约束局部变化。不能只对已有硬拼接结果取梯度，再把同一个结果当颜色目标，这样会保留其接缝。当前采用加权重叠融合，不同相位的木纹或条纹经平均可能变软，结构引导不能保证消除这种误差；应结合报告和实际图像评价。相关原理见 [Image Melding 作者项目页](https://web.ece.ucsb.edu/~psen/melding.html) 与 [Bhat 等 screened Poisson 原始论文](https://grail.cs.washington.edu/projects/screenedPoissonEq/screenedPoissonEq_files/screenedPoissonEq.pdf)。

背景引导和最终重建的固定边界均使用写入掩膜外的原图值。被 `--source-exclude-mask` 排除但留在外部的像素、被保护而保留的字样，仍可能通过边界影响相邻修补；它们不会因此变成供体或可信原图匹配样本。只有原允许掩膜可写入，最终保留掩膜外 RGB 及原 alpha。

精修预算为最多 4 万选区像素、100 万包含边界扩展的上下文像素、2000 个目标块中心及累计 1.28 亿匹配位置。背景引导与最终 screened Poisson 求解各自最多 500 次迭代；以重新计算的方程残差检查收敛，不只检查迭代更新量。低支持传播块单独计数，不把继承时的零占位误差算入独立匹配误差分位数。这些诊断衡量实现、支持和数值状态，不是真实背景恢复精度。

这是自行编写的局部、有界工程实现，使用 NumPy / OpenCV 处理供体、颜色、梯度及线性求解；未复制开源参考实现，未捆绑模型权重，不代表完整 Image Melding、Wexler 或 PatchMatch 论文复现。供体不足、颜色或梯度覆盖不足、资源预算或求解失败均报错，不静默回退初始结果或其他算法。

同一次调用内部完成初修与精修，用户不需要手工串联。强规则纹理、锐利轮廓与文字结构仍可能出现相位错位、重复、颜色变化、软化或接缝；成功输出继续保持 `needs_review`。默认工作流程是执行方式的选择，不是各类图像均优于旧方法的质量声明。

## 供体排除与有依据的修正

`--source-exclude-mask` 表示“这些像素不能借用或用于可信匹配”；`--protect-mask` 表示“这些像素不能修改”。两者用途不同：供体排除不扩大或缩小允许写入选择区，即使某个位置被排除为供体，它在原修补掩膜内仍可能被重建。需要禁止写入时应另外使用保护掩膜。使用 consensus 时，写入掩膜外仍以原图作为固定 Poisson 边界；被源排除但保留在外部的像素可能影响邻近修补颜色，即使它们完全不参与供体选择或匹配。保护区中仍有水印时也有这一限制，不可为回避边界影响而自行扩大写入掩膜。

该 CLI 参数必须配合显式 `--method exemplar`，不接受 auto 或其他方法，也不支持批量共享。限制方法是为了保留用户指定的供体语义：排除后缺少源块直接报错，不能静默切到 NS 或其他恢复方法。

首轮检查若发现复制进了桌沿短线、邻近正常文字或明显异材质，可由 Agent 根据原图可见位置生成供体排除掩膜。算法本身没有语义材质分类器；掩膜必须有可观察依据。

集中列出首轮可见问题后，继续使用原始图像与保护掩膜。选择区正确时保留其范围，只新增有依据的供体排除掩膜；确有漏选或误选时先按原图修正这些位置，再运行 `exemplar --refine consensus` 并输出到新路径。这样不会累积首轮修复图中的人工内容，也无需用户手动串联算法。每轮修正对应具体证据并比较效果，不通过无目的调参或扩大擦除范围凑出成功。保持 `needs_review`，若仍有异常如实说明。较高 quality 会改变初修预算，不能保证更适合当前材质。

## Telea / Navier–Stokes 局部插值

使用 OpenCV `inpaint` 的两个传统实现。Telea 通过快速行进法从边界向缺损区推进并加权估计；Navier–Stokes 方法沿图像结构传播信息。它们依赖邻近像素，适合细小遮挡及平缓背景；复杂纹理、人物五官、独特文字与几何细节常会模糊或失真。[OpenCV 原理与文献索引](https://docs.opencv.org/4.x/df/d3d/tutorial_py_inpainting.html)

保留两个显式传统入口。未知区域的 auto 主路为 Exemplar，仅在供体/预算不足时回退 NS；显式 exemplar 或 consensus 失败直接报错。旧版仅比较边界平滑度，容易偏向涂抹；当前不使用该分数淘汰有纹理的结果。局部插值与非局部修复均标为 `needs_review`，不使用生成式模型。

当前插值限额包括局部处理区域不超过 400 万像素、掩膜不超过 20 万像素、不超过整图 8%、最大内部深度不超过 20 像素。限额针对局部修复路线，避免把大片不透明遮挡当作小水印悄悄插值。报错时应缩小到真实字形或明确告知无法可靠恢复。

## 验证应分成两个问题

1. **是否只改了允许的区域？** 比较输入与保存后重新解码的 PNG，校验尺寸、输入哈希、alpha 和掩膜外像素，并确认实际写入掩膜没有越过允许修补区。这里可以给出精确的零改动计数。
2. **改后的内容是否等于真正原图？** 只有干净原图才能计算有意义的真值误差。没有真值时只能观察残影、颜色与结构连续性，并明确算法假设。自洽合成测试验证实现和回归，不能替代真实图的精度评估。

- [Newson 等：Non-Local Patch-Based Image Inpainting，IPOL 2017](https://www.ipol.im/pub/art/2017/189/)：作者论文与参考实现入口；描述重叠加权重建、多尺度与纹理匹配，也讨论平均造成的纹理模糊。
- [Darabi 等：Image Melding，SIGGRAPH 2012](https://web.ece.ucsb.edu/~psen/melding.html)：作者项目页与论文入口；颜色/梯度补丁表示和 screened Poisson 重建。
- [Bhat 等：Fourier Analysis of the 2D Screened Poisson Equation，ECCV 2008](https://grail.cs.washington.edu/projects/screenedPoissonEq/)：作者论文与求解器资料，说明颜色数据项和梯度约束的权衡；本包未复制其 Fourier 求解实现。
- [Barnes 等：PatchMatch，SIGGRAPH 2009](https://www.connellybarnes.com/work/publications/2009_patchmatch.pdf)：近似最近邻搜索及其与补丁投票重建的关系；本包未实现随机 PatchMatch。

实现由本 Skill 的独立脚本与公开库 API 组成；没有复制或捆绑这些论文的开源参考实现、论文文件或第三方模型代码。需要解释某个具体算法时直接引用相应原始资料，不把未实现的研究方法列为本版本能力。

## 环境

要求 Python 3.10 或以上，依赖清单在根目录 `requirements.txt`。先运行 `scripts/bootstrap.py --check-only`；返回 `missing_dependencies` 时可运行 `--install`。成功响应包含 `status=ready`、实际 `python` 路径和库版本。后续必须使用该解释器，不能假定系统 `python` 已安装依赖。

bootstrap 复用可导入三个图像库的当前解释器，否则按依赖清单的摘要建立独立缓存 venv。它检查导入是否成功并记录版本；不会强制替换已经可用的当前环境。默认缓存使用系统用户缓存目录，可通过 `--cache-dir` 指定。首次安装需要可访问的 Python 包源；处理图片和离线自测不需要网络或 GPU。依赖清单不等于所有操作系统的安装保证；安装失败时保留具体错误，勿循环重装。

## 参数

| 参数 | 语义 |
| --- | --- |
| `--input PATH` / `--input-dir PATH` | 单张或批量，二选一 |
| `--output PATH` | 单张 PNG 路径；默认当前目录下 `watermark-output/原名_clean.png` |
| `--output-dir PATH` | 输出目录；单张时不能同时给 `--output`；批量默认输入目录的同级 `原目录名_cleaned` |
| `--profile auto` | 遍历内置模板；当前只有 WorkBuddy 模板 |
| `--profile workbuddy` | 指定内置 WorkBuddy 模板，完整 id 为 `workbuddy-corner-v1` |
| `--profile none` | 不进行模板检测，配合手动区域；无手动区域时自动模式跳过 |
| `--profile /absolute/profile.json` | 使用本地配置与同目录模板；见 profiles.md |
| `--mask PATH` | 与摆正后输入尺寸相同的掩膜，非黑且 alpha 大于零的像素选中 |
| `--roi x0,y0,x1,y1` | 允许修复的矩形，右下边界不含；与 `--mask` 互斥 |
| `--protect-mask PATH` | 保留区域，规则同 mask；从最终修补区域减去 |
| `--source-exclude-mask PATH` | 与摆正后原图同尺寸，规则同 mask；选中区域不用于 exemplar 的供体或可信匹配，不扩大写入范围、不保护该区域；必须与 `--method exemplar` 合用 |
| `--text-roi x0,y0,x1,y1` | 包住完整文字行的局部区域；提取浅色字芯、暗描边及抗锯齿，写入限定框内，统计可读取框外最多 32 像素；非整块矩形修复 |
| `--corner-text` | 已知模板未命中后尝试保守底角候选，实验入口，常会跳过；默认关闭 |
| `--method exemplar` | 从同图局部完整图像块借纹理，允许有上限的照明偏移 |
| `--refine none` | 可选 `none` / `consensus`，CLI 默认 `none` 保留兼容；Skill 的未知纹理流程显式传 `consensus`，必须配 `--method exemplar`，完成背景/结构引导、初修检查、重叠供体融合与梯度重建 |
| `--quality balanced` | `fast` / `balanced` / `high` 控制初始 exemplar 的有界图像块与搜索预算；consensus 参数固定，不随 quality 改变 |
| `--method auto` | 依证据选择纯色、模板反算或 Exemplar；供体/预算不足才回退 NS |
| `--method inverse` | 必须匹配半透明 alpha 模板，不会凭手动矩形假定透明度 |
| `--method fill` | 仍须通过纯色背景检查，不是无条件矩形填色 |
| `--method telea` / `--method ns` | 指定 OpenCV 传统局部插值，仍受区域限额约束 |
| `--radius 3` | Telea/NS 插值邻域，有限浮点数，范围 1–15；与实际后端一致 |
| `--dilate 0` | 手动掩膜/矩形的显式膨胀半径，整数 0–64；默认不扩展 |
| `--scale FLOAT` | 显式模板等比例缩放，有限数，范围 0.125–8；不改变输入图尺寸 |
| `--max-pixels 40000000` | 输入像素上限；提高前先考虑可用内存 |
| `--max-workers 2` | 批量外层并发，整数 1–8；每个 OpenCV 操作仅一个线程 |
| `--recursive` | 批量读取子目录，保持相对目录关系 |
| `--no-preview` | 不生成局部前后对比图与选择范围叠加预览；处理图、两种掩膜与报告仍生成 |
| `--report PATH` | 自定义单张报告路径；默认与输出同名的 `.report.json` |
| `--overwrite` | 可覆盖已有结果；永不允许覆盖输入、掩膜和 Skill 资源 |
| `--strict-classical` | 声明纯传统算法；省略时也不启用任何学习模型 |
| `--list-profiles` / `--version` / `--help` | 查看配置、版本和实际参数，不需要输入图片 |

手动区域与默认 `auto` profile 一起使用时，区域优先，不自动改处理其他位置的模板。显式指定 profile 或使用 `inverse` 时仍做模板检测；给定 ROI 同时限制搜索，模板自动反算只写入其支持范围与手动区域的交集。保护区域最后扣除，不参与修补。

`--source-exclude-mask` 可与 `--text-roi`、`--mask`、`--roi` 中任一入口以及 `--protect-mask` 同时使用，但只接受显式 `--method exemplar`。与 `auto`、`telea`、`ns`、`fill`、`inverse` 合用均报错，避免回退方法改变指定的供体约束。它不会从修补范围中扣除像素；需要保留像素应使用 `--protect-mask`。它可与 `--refine consensus` 同时使用；被排除但处于写入掩膜外的像素仍保留为 Poisson 固定边界值，可能影响邻近修补，但不会因此参与供体或可信匹配。

批量模式不接受 `--output`、`--report`、`--mask`、`--protect-mask`、`--source-exclude-mask`、`--roi`、`--text-roi`。不同图片的供体排除区域需逐张判断，不能共享一个批量掩膜。支持的批量扩展名为 PNG、JPG/JPEG、WebP、BMP、TIF/TIFF，每个文件仍需是单帧受支持模式。子目录中的输出目录会排除，避免把结果再次当输入；输出目录不能等于输入目录。发生不区分大小写的目标重名时预先报错，不静默覆盖。

## 报告解释

单张 stdout 是 JSON 摘要，包含输入、输出、报告路径、状态、实际方法和验证值。详细报告另外包含以下内容：

- `input`：输入 SHA-256、原始编码尺寸、摆正后尺寸、输入模式及 EXIF 方向处理标记。
- `detection`：模板 id、坐标、相似度和一致性指标；不会输出大数组。分数不是概率。
- `restoration`：实际方法、假设、警告、是否需检查、参与修补与实际改变的像素数。
- 文字检测的 `detection.diagnostics`：只读上下文范围、初始与最终中值核、字形几何尺度、是否二次估核、细桥分离及恢复范围、短暗轮廓延伸数量，用于解释选择区变化。
- `restoration.refinement`：完整供体数、邻域外但仍在有界上下文内的搜索次数、累计匹配位置、低支持传播数、独立匹配误差、聚合方式、初修信息保留/替换数、双侧可见线检查，以及背景引导与最终重建的求解状态。传播块不以零匹配误差计入独立误差分位数。
- `validation`：重新读取保存后的 PNG，核验尺寸、alpha、掩膜外像素和输入文件哈希。
- `write_mask` / `artifacts`：实际写入掩膜的外接框和各产物路径。
- `true_original_accuracy=null`：无干净原图时不提供虚构的恢复准确率。

| 状态 | 后续动作 |
| --- | --- |
| `processed` | 交付前查看对比图及算法假设 |
| `needs_review` | 说明近似修补或数值疑点，交付对比图供观察 |
| `skipped_no_match` | 说明未命中支持的模板；若仍有水印，使用明确手动区域 |
| `skipped_empty_mask` | 检查掩膜是否为空、完全透明或全被保护区域扣除 |
| `error` | 读取错误原因并修复具体输入或参数；不声称生成了可用结果 |

退出码：`0` 为单张处理/跳过成功或批量无错误；`1` 为批量有部分错误，已成功项保留；`2` 为单张错误或全局参数/运行错误。`needs_review` 仍为 `0`，因此应同时读取状态。

运行错误在 stderr 输出 JSON；argparse 的语法错误输出标准用法提示。显式给定且安全的 `--report` 会尽可能写错误报告；依赖缺失、目标冲突或路径受保护时可能仅有 stderr。批量每项有独立报告，并在 `summary.json` 汇总。失败可能发生在部分产物写出之后，应以报告状态为准。

## 像素与元数据范围

范围验证以按 EXIF 方向摆正并转成 RGB/RGBA 的输入解码像素为基准，不承诺文件字节相同。JPEG 输入输出为 PNG，避免重新 JPEG 压缩改变整图。PNG 写入采用内存编码、临时文件及原子替换。

保留可通过 Pillow 传递的 ICC、EXIF、DPI 和文本信息；不要声称保留所有格式专属元数据，也不要声称修改后签名或内容凭证仍有效。透明区域不作模板反算，完全透明像素排除在修补之外，原 alpha 数值逐像素保留。


## 通用区域、掩膜与输出

`--text-roi` 与 `--mask`、`--roi` 互斥；不与 `--dilate` 或 `--method inverse` 合用。它在给定框内估计浅色文字和暗轮廓，不使用任何品牌字形模板。框应包住完整一行文字，并只留少量背景；过高或横跨多种主体的框不适合稳定分割。上限 100 万像素，未检出一致文字行时明确报错，不自动用矩形擦掉。

1.3.0 在框外最多 32 像素只读上下文上完成中值统计，避免裁片边界补齐造成同一像素的背景估计变化。亮种子具备足够内部支撑时，先分离可能连接场景与字形的一像素细桥；按可靠字行高度最多重新估核一次，再在选定字形附近最多 3 像素内恢复原亮种子。始终按字高保留下伸笔画余量，形态学扩张继续受深色边缘约束。只读上下文不扩大允许修补区域，也不保证任意宽框都得到相同且正确的字形；仍须查看选择区预览。

细钩字芯过弱时，可以按已观察描边的对比度，在原字形附近沿有双侧暗谷证据的轮廓有界延伸最多 3 步，并补一圈弱抗锯齿边。该处理不依赖样例坐标，不是把所有暗纹或整个字框一起扩大选中。

`--corner-text` 不能与手动区域同时给出；只扫描底角，在边界、排布或多候选不确定时跳过。它不能确认文字在语义上是水印。可优先由 Agent 看原图后给 `--text-roi`，不要求用户制作模板。

`--quality` 的初始 exemplar 配置：fast 为图像块半径 4、搜索半径 80；balanced 为 5、112；high 为 7、144。初始 Exemplar 默认局部上下文不超过 100 万像素、修补掩膜不超过 4 万像素、迭代不超过 2000（fast 1800）。consensus 使用独立固定参数，不随 quality 改变。明确指定 exemplar 超限就报错；auto 记录失败原因并仅回退一次 NS，NS 也失败则整个结果报错。

新增 `.selection.png` 保存保护区扣除后的允许修补范围，`.selection-preview.png` 用粉色覆盖显示它，便于发现漏字和误选。原 `.mask.png` 仍保存实际改变的像素，两者可能差几个本来就与估计颜色相同的像素。详细报告新增 `selection_mask` 与 `restoration.exemplar`（供体匹配误差、距离、颜色补偿、固定预算等）。供体误差不是真实原图的恢复误差。

完整污染掩膜在扣除保护区前保留，被保护的残余文字不会用于匹配或作为纹理来源；完全透明像素也不会当作可靠来源。文字掩膜另加 2 像素源排除圈，只影响供体与可信匹配，不扩大 `.selection.png`。初始贪心填充允许同一目标补丁内的更远可信像素跨过排除圈提供支撑，圈内原图像素仍不参与匹配。所有输出仍只写入最终允许区，alpha 保持不变。图片查看缩略图不得取代原始输入路径。

## 完整修复与精修

`--refine consensus` 只接受显式 `--method exemplar`；与 `auto`、`fill`、`inverse`、`telea`、`ns` 合用时报错。Skill 对未知水印和有纹理背景明确传入这两个参数；省略 `--refine` 或指定 `none` 时，CLI 仍保留原方法流程，auto 不会自行启用 consensus。

同一次调用完成初修、背景引导、初修一致性检查、可见结构支撑、重叠供体融合及最终重建。初修并未删除：它提供求解初值，且与原图局部背景变化相容的部分可继续作为弱匹配支撑；遮挡两端都能从干净原图确认方向一致的可见边缘时，相应初修线段也可保留为弱支撑。其余不相容部分用原图固定边界求解的低频背景代替。估计图不成为真实供体。无需用户手工串联两次算法，也不要把初始处理图重新作为 `--input`。模板和近纯色仍可走原有对应分支；需要快速初修时指定 `--refine none`。

文字区域示例：

```bash
python scripts/run.py --input original.png --text-roi 100,100,360,180 --method exemplar --refine consensus --quality balanced --output clean.png
```

精确写入掩膜与额外供体排除示例：

```bash
python scripts/run.py --input original.png --mask watermark_mask.png --source-exclude-mask donor_exclude.png --method exemplar --refine consensus --output clean.png
```

精修使用真实原图内的 19×19 完整供体，以空间高斯权重和匹配误差加权融合重叠颜色与各供体内部梯度，再进行 screened Poisson 求解。低支持传播块的融合权重另行降低。只写入原允许掩膜，不扩大范围。局部 112 像素搜索邻域内无完整来源时，可搜索同一次已限定的上下文；有效匹配支撑不足的块可继承受支持邻块的供体提案，完整性及源排除规则始终有效，不把图像边缘的反射像素当新供体。加权平均仍可能软化细木纹，不能保证原纹理相位正确。

`--quality` 只调整初始 exemplar 预算，精修参数不随档位变化。精修上限为 4 万选区像素、含边界扩展的 100 万上下文像素、2000 个目标块中心，以及累计 1.28 亿匹配位置。背景引导和最终重建各自最多 500 次求解迭代；匹配误差仅统计有独立匹配支撑的块，低支持传播块单独计数。预算和收敛仅说明计算状态，不证明纹理或结构正确。

可见线保护最多检查 128 个线段提案，只有遮挡两端附近各至少 8 个方向一致的干净边缘样本支持时才接受。可信边缘超过 5 万像素时跳过这一保护并报告警告，继续按其余背景证据处理；不是整张修复失败，也不声称已检查超限的结构。

无合格供体、颜色或梯度约束覆盖不足、资源预算不足或求解失败时明确报错；不静默交付未精修结果，也不回退 NS。成功输出仍需复核强规则纹理、锐利轮廓和正常文字附近的残影、相位错位、重复、色差、软化与接缝。默认流程不意味着每张图均优于初修；报告中的匹配误差与求解残差不表示真实原图恢复准确率。

背景引导与最终重建均以写入掩膜外的原图值作为固定边界。因此，被 `--source-exclude-mask` 排除或被保护而保留在外部的像素仍可能经边界条件影响邻近修补颜色；其原图值不会成为供体或可信匹配样本。若边界仍含受保护的水印，应如实说明这一限制，不能为改善颜色自行扩大写入区域。

## 集中检查后有依据的修正

当局部对比显示修补区借入了邻近异材质、正常文字或桌沿短线时，先在原图中定位这些不适合借用的区域，再生成 `donor_exclude.png`。掩膜须与朝向归一化后的原图同尺寸，非黑且非透明像素表示排除。算法仅执行像素约束，不提供语义材质识别。

保持原始 `--input` 与原 `--protect-mask`，先集中检查选择区、残字、色块和结构问题。选区正确时保留原范围，只增加供体排除掩膜；选区有明确漏选或误选时先依据原图修正，再执行完整流程并使用新输出路径。下面的 ROI 仅为坐标示例，实际调用应使用检查后的当前坐标：

```bash
python scripts/run.py --input original.png --text-roi 100,100,360,180 --method exemplar --refine consensus --quality balanced --source-exclude-mask donor_exclude.png --output refined.png
```

每轮修正须对应原图和对比图中已观察到的原因，比较改善后收敛；不把首轮处理图重新作为输入，不通过无目的调参、扩大擦除区域或反复运行保证成功。排除掩膜不改变 `--protect-mask` 的语义，也不会扩展 `.selection.png`。源块不足会报错，不进行 NS 回退；有输出时继续保持 `needs_review`，复核选择范围、残字与结构连续性。

## 本轮实测（tests/run_test.py + tests/run_attack2.py）

**测试链路**：合成测试图 → embed（水印「©十七° shiqidu@2026」，password=7，输出 184 bits）→ 施加攻击 → verify 提取比对。

| # | 场景 | 结果 | 判定 |
|---|---|---|---|
| 1 | 无损 PNG 原产物直取 | 100% 逐字命中（match_ratio 1.0） | match ✅ |
| 2 | JPEG q85 重压缩（模拟微信/平台二压） | 94.1%（18 字符仅「©」受损） | match ✅ |
| 3 | 缩小 50% 再放回原尺寸（LANCZOS，模拟压图床再下载） | 100% 逐字命中 | match ✅ |
| 4 | 属性被剥离 + 不提供凭证 | 正确跳过频域提取，输出提示补凭证 | 按设计 ✅ |
| 5 | 裁剪 20%（顶部+右侧） | 提取失败 | no-match（诚实边界） |
| 6 | 缩小 50% 不回弹 | 提取失败（match_ratio 0.0） | no-match（诚实边界） |

**属性层验证**：无损产物 EXIF 读取到 Artist / Copyright / ImageDescription（含水印文本）/ wm_bits 全部字段；PNG 产物 tEXt chunk 同样齐全。

## 与官方宣称的差异（重要）

blind-watermark 官方 README 宣称可抗 50% 裁剪，**本轮实测未复现**（裁剪 20% 即失败）。本包所有对外文档（SKILL.md / README.md）一律按实测数据书写，不宣传抗裁剪能力。这是本 Skill 与市面同类工具的核心差异：只承诺验证过的事。

## 已知限制

- 截图、AI 重绘、强抹除会破坏盲水印（未纳入自动化测试，按算法原理推断，文档已如实标注）。
- `wm_bits` 无法从水印文本推算（18 字符实际 184 bits），必须使用 embed 输出的真实值；脚本已通过元数据 + 凭证双通道解决，但若图片属性被剥离且用户丢失凭证，频域层无法查验——这是机制固有属性，非缺陷。
- 清除动作无无损方案（频域加性修改不可逆），`from-original` 模式依赖用户保留无水印原图。
- 未在 macOS / Linux 实测；未测试动图（GIF/WebP 动帧）与 CMYK 色彩空间。
- 脚本输出为一行 JSON（欢迎语已静默）；exit 2 表示文件不存在或缺凭证。

## 分发静态检查

SKILL.md frontmatter 已核验：name 与目录名一致，description 含触发词与「可见水印不在范围」的排除声明。脚本为单文件无外部配置依赖。归档不含真实用户图片、密码、凭证或私有路径信息；测试产物（临时图片）已清理，仅保留测试脚本本身。
